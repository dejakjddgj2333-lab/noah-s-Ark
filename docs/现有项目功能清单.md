# 现有项目功能清单（基线盘点）

> 盘点时间：2026-09-30。用途：作为"邀请返佣与等级体系"开发前的功能基线。
> ⚠️ 规则：**已有功能一律不动**，修改任何现有功能前必须先征得同意。
> 前端：`app/`（Flutter，包名 mingce，显示名 Noah's Ark / 明策）
> 后端：`server/`（FastAPI + SQLAlchemy async + JWT，路由统一挂 `/api` 前缀）

---

## 一、后端功能（server/）

### 1. 认证模块 `routers/auth.py`（/api/auth，全部公开）
| 端点 | 用途 |
|---|---|
| POST /api/auth/send-email-code | 发送邮箱验证码（60s 防重发，10min TTL；SMTP 未配置或 EMAIL_VERIFY_ENABLED=false 时回显 debug_code） |
| POST /api/auth/register | 用户名+密码+邮箱+验证码注册，注册即签发 JWT |
| POST /api/auth/login | 用户名密码登录，返回 JWT + 用户 |
| GET /api/auth/me | 当前用户信息（需 Bearer JWT） |

- 用户名规则 `^[a-zA-Z0-9_]{3,32}$`；JWT 为 jose HS256，sub=用户 id，默认 24h
- **仅支持用户名+密码登录**，无邮箱登录、无换绑邮箱端点

### 2. 资讯模块 `routers/news.py`（/api/news，公开）
- GET /api/news — 列表（category/source/lang 分页，仅 published，不带正文）
- GET /api/news/{id} — 详情（带正文，英文备份字段）

### 3. 行情模块 `routers/market.py`（/api/market，公开，代理 OKX REST，tenacity 重试）
- tickers（SPOT/SWAP）、单交易对 ticker、K 线 candles、资金费率 funding-rate

### 4. 市场总览 `routers/overview.py`（/api/market-overview，CoinGlass/CoinGecko 透传 + TTL 缓存，未配 key 返回 503）
- 恐慌贪婪、爆仓统计/订单流、费率对比、巨鲸异动、全局市值、多空比、多维指标卡（ahr999/pi_cycle/puell 等）

### 5. 数据表（models/）
- **hk 自有表**（启动 create_all）：
  - `hk_users`：id、username(唯一)、password_hash、email(唯一)、email_verified、avatar_url、status(active/banned)
  - `hk_email_codes`：email、code、purpose、used、expires_at
- **共享只读表**（okx 侧管理，hk 不动）：`news_articles`（含中英双语、分类、互动计数）
- ⚠️ 无 Alembic 迁移、无定时任务、无测试目录

### 6. 与"邀请/返佣/等级/资金"的关系
**完全没有相关代码**（全库搜索 invite/referr/commission/level/holding/withdraw/balance/wallet 等零匹配）。所有资金、返佣、等级功能需从零新建，不会与现有代码冲突。

## 二、前端功能（app/lib/）

### 目录结构
仅 4 层：`main.dart` + `core/`（theme.dart 配色 + widgets.dart 公共组件）+ `pages/`（14 个页面）+ `services/`（api/data/auth/ticker_ws 四件）。无独立 models/widgets 目录。

### 页面清单
**命名路由**（main.dart，含登录门控）：
- `/login` → 登录/注册一体页（双模式切换，验证码 60s 倒计时，dev 自动回填 debug_code）
- `/deposit` → 充值页 — ⚠️ 需登录，但**纯静态 mock，无接口调用**
- `/commission` → 返佣/佣金页 — ⚠️ 需登录，但**纯静态 mock，无接口调用**

**底部 4 Tab（McShell）**：
- 首页：6 个子 Tab — 综合看板 / 行情榜单 / 多维指数终端 / 多空爆仓 / 巨鲸雷达 / 资金费率矩阵
- 资讯：快讯/投研/宏观/政策 + 详情页
- 社区：聊天群组列表 — ⚠️ 纯静态 mock
- 我的（资产中心）：入口跳充值/返佣、设置项 — 未登录显示登录引导占位

**push 路由**：MarketDetailPage（K线+费率详情）、NewsDetailPage

### 服务层
- `services/api.dart`：HTTP 客户端（10s 超时、Bearer 支持、统一 ApiException）；baseUrl 默认 `http://shipapi.bdxapi.com`，`--dart-define=API_BASE` 可覆盖
- `services/auth.dart`：AuthStore 单例（token 持久化到 SharedPreferences，启动恢复）
- `services/data.dart`：行情/资讯数据模型与获取（503/502 时回退 mock）
- `services/ticker_ws.dart`：直连 OKX 公共 WS 订阅 tickers（心跳+自动重连）

### 已知问题/注意点（新功能开发时留意）
1. **token 未附加到业务请求**：McData 各方法未传 Authorization 头，登录态实际没生效（除 /deposit /commission 路由门控外）
2. `/deposit`、`/commission`、社区页是**静态演示 UI**——返佣功能开发时可直接重做这两个页面（需先征得同意，因为它们属于"已有页面"）
3. 多处 overview 接口有 mock 回退逻辑

### 关键依赖
http、shared_preferences、web_socket_channel、google_fonts、cupertino_icons

## 三、对"邀请返佣与等级体系"开发的影响评估

| 事项 | 结论 |
|---|---|
| 与现有功能冲突 | **无**。后端无任何资金/返佣/等级代码，全部新建 |
| 需要修改的现有功能 | ① hk_users 表需加字段（邀请码/上级/等级相关）——改表结构需同意；② /commission、/deposit 两个静态页需重做为真实功能——改页面需同意；③ token 附加问题需修复——改 api.dart 需同意 |
| 可直接新增 | 新路由文件、新表、新前端页面（新文件名）、结算定时任务 |
| 联调基础 | 前端默认已连线上后端 shipapi.bdxapi.com；本地后端可用 `--dart-define=API_BASE=http://localhost:8000` 切换 |
