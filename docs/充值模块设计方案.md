## 一、业务流程

```
用户打开 APP 充值页
  → 选择网络（先支持 TRC20）
  → 平台返回该用户在该网络上的专属收款地址（长期固定）
  → 用户从自己的钱包/交易所转入 USDT
  → 平台扫链服务监听该地址入账交易
  → 达到确认数 → 自动入账到【本金账户】
  → 充值记录可查，APP 余额自动可见
```

- 到账资产统一折算/入账为 **USDT**
- 充值进入**本金账户**（收益账户只放产品收益与佣金，见需求文档第六节）
- 入账依据：唯一业务流水号（链上 txid + 地址 + 金额），**重试/重复回调不得重复入账**

## 二、架构（自建扫链方案）

| 组件 | 职责 |
|------|------|
| 平台钱包体系 | 平台控制一批链上地址的私钥；用户充值地址 = 平台分配的子地址，充值实质是给平台转账 |
| 充值地址服务 | 为用户分配/查询专属充值地址（每人每网络一个固定地址，可收藏复用） |
| 扫链监听服务 | 持续扫描充值地址的 USDT 入账，按确认数确认（部署在服务器长期运行） |
| 自动入账 | 确认后：写充值流水 → 本金账户余额增加 → 充值记录可查 |

## 三、已定参数

| 参数 | 定稿值 | 说明 |
|------|--------|------|
| 首批网络 | **TRC20** | 跑通后按需加 ERC20/BSC 等 |
| 确认数 | **12 个确认**（约 1 分钟） | 可调 |
| 地址策略 | **每人每网络一个固定地址** | 简单、体验好 |
| 最小充值金额 | **≥10 USDT** | 过小金额不够手续费 |
| 入账账户 | 本金账户 | 收益账户不收充值 |
| 私钥管理 | 开发期平台热钱包；生产建议硬件钱包/托管 | 待运维方案 |

## 四、技术要点

- 本地开发用 **TronGrid API**（免费）监听入账，无需自建节点；生产可换自建节点或付费 API
- 充值流水表须含：txid、网络、地址、金额、确认数、状态、入账时间，txid 唯一约束防重
- 金额精度与取整规则：USDT 6 位小数原值入账（需求文档第九节第 6 条提现精度另行定义，充值不设截断）
- 错链/错币场景：文档第九节第 5 条未完全定稿，本期先记录流水状态 `unmatched`，人工经客服流程处理（第八节异常转交流程）

## 五、接口规划（Phase 6）

- `GET /api/deposit/address?network=trc20` — 查询/分配我的充值地址
- `GET /api/deposit/records` — 充值记录（含确认数/状态）
- 扫链服务内部：轮询 TronGrid → 确认 → 入账（幂等）
